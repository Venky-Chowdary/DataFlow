## How to re-run

```bash
# fleet (repo root): PostgreSQL, MySQL, MinIO, fake-gcs, Azurite, ...
docker compose --profile amd64-sql up -d

cd apps/api
DATAFLOW_SCALE_FILE_MATRIX=1 python -m tests.scale.file_matrix            # 100K, whole matrix
DATAFLOW_SCALE_FILE_MATRIX=1 python -m tests.scale.file_matrix --list     # cell inventory
DATAFLOW_SCALE_FILE_MATRIX=1 python -m tests.scale.file_matrix \
    --only csv,parquet --route file_to_postgres --store minio --rows 100000
python -m tests.scale.report --out ../../docs/SCALE_MATRIX_FILES.generated.md
```

Without `DATAFLOW_SCALE_FILE_MATRIX=1` the harness exits as a skip, so CI without the
fleet never pretends to have measured anything. Fixtures (~32 MB per format at 100K)
are generated into `~/dataflow_scale_fixtures` by `tests/scale/dirty_fixture.py` and are
not committed. Results append to `apps/api/exports/scale/file_matrix.jsonl` (git-ignored),
one JSON record per cell, so a re-run of one fixed cell supersedes its earlier record.

## What each cell proves

| evidence | how it is obtained |
| --- | --- |
| destination row count | fresh `psycopg2` / `PyMySQL` connection doing `COUNT(*)`, or an independent third-party reader (pyarrow, fastavro, openpyxl, defusedxml) for files; never `TransferResult.records_transferred` |
| content checksum | SHA-256 over the mapped projection, cell-by-cell canonicalized, compared against the checksum computed from the fixture generator |
| quarantine | row count in the destination's `*_df_quarantine` DLQ table, compared against the number of deliberately untypeable rows the generator planted |
| object stores | independent MinIO/GCS/Azurite client, listing every object under the prefix rather than probing one expected key |
| fail-closed | separate `strict` cells: one untypeable cell must abort the job and leave `COUNT(*) = 0` |

The engine's own claim is recorded alongside the independent count so a divergence
between "reported" and "landed" is visible rather than hidden.

## Dirty-data fixture

`tests/scale/dirty_fixture.py` generates 100,000 rows per format containing embedded
delimiters and quotes, newlines inside quoted fields, non-ASCII text, leading-zero
account codes that must stay text, four date spellings, offset-bearing timestamps,
very long strings, scientific-notation decimals, nulls spelled `""` / `NULL` / `\N`,
and 9 rows whose `qty` is untypeable text (the quarantine population). Structural
variants cover BOM present/absent, UTF-16 and latin-1 encodings, ragged rows,
duplicate header names, and Excel trailing blank rows/columns.

## Defects found and fixed (root cause, one owner module each)

| defect | root cause | owner module changed |
| --- | --- | --- |
| every on-disk XML source was refused as "unmeasured" | `prepare_stream_content` hands a filesystem path down as `str`, but the XML readers treat `str` as *document text*, so the path string itself was parsed as the document | `src/transfer/file_stream.py` — `_xml_source()` normalizes a path source to `Path` before count and iteration |
| `.psv` (pipe-delimited) rejected as `Unsupported file type: unknown` | both detectors classified by extension first and `.psv` was unlisted, even though the delimited reader already sniffs `\|` as a candidate separator | `services/file_parser.py` — `detect_format` / `FileParser.detect_file_type` |
| a BOM-declared UTF-16 CSV died with `line contains NUL` | `detect_encoding` recognized only the UTF-8 BOM; UTF-16 bytes failed the UTF-8 probe and fell through to latin-1, decoding every second byte as a NUL character | `services/csv_profiler.py` — `detect_encoding` treats a declared UTF-16/32 BOM as authoritative |
| an offset-bearing timestamp bound to a declared `TIMESTAMPTZ` lost its offset | the writer normalized the declared type first, and `normalize_logical_type("timestamptz")` collapses to `"datetime"`, so the timezone-aware DDL never reached `coerce_sql_temporal` | `connectors/writer_common.py` — resolve temporal DDL from the *declared* type, fall back to the normalized one |
| an explicit `""` in JSON/JSONL/Parquet was silently written as NULL | `_json_empty_to_none` recursively rewrote empty strings for self-describing carriers, which do spell NULL separately — that is data loss, not normalization | `src/transfer/file_stream.py` — helper removed; only delimited carriers treat a blank field as absence, because RFC 4180 has no NULL token |
| fake-gcs emulator traffic went to the public endpoint | `_resolve_endpoint` consulted `connection_string`/`host` before the explicit `endpoint_url` | `connectors/gcs_common.py` |

Regression tests: `tests/test_file_stream_xml_path_source.py`,
`tests/test_psv_delimited_detection.py`,
`tests/test_csv_utf16_encoding_detection.py`,
`tests/test_carrier_empty_and_offset_fidelity.py`.

Two harness (not product) errors were also corrected, because a wrong measurement is as
damaging as a wrong write: the latin-1 fixture was compared against a UTF-8 checksum, and
the independent Excel reader read `values_only`, which flattens a preserved `''` (a typed
cell with no text run, `<c t="inlineStr"/>`) into NULL and would have accused the writer of
a loss the file does not contain.

## Correct refusals (fail-closed, proven not fixed)

These are *not* defects — the engine refuses rather than inventing data, and the cell
proves the destination stayed empty:

- ragged CSV rows: refused (`CSV row has 13 value-bearing cells but the header names 11
  column(s); refuse silent column drop`), destination `COUNT(*) = 0`. Quarantine is the
  answer for a bad *cell*; a ragged row is a disagreement about which column a value
  belongs to, and guessing would move values into the wrong columns.
- legacy BIFF `.xls`: refused (`Legacy .xls is not supported. Save the workbook as .xlsx`).
  No BIFF reader is shipped and BIFF8 caps a sheet at 65,536 rows, so a 100K `.xls`
  cannot exist. Documented as unsupported rather than faked.
- `.zip` container: refused. The reader handles gzip only; the archive is rejected as
  undecodable bytes rather than misparsed. The message names the encoding, not the
  container — cosmetic, and worth a clearer error.
