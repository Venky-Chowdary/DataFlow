## Reverts/decisions

- **PR #334 (PostgreSQL TLS no-downgrade) was reverted, then re-applied with an explicit `ssl_mode`.** The no-downgrade fix and its `target_sample` follow-up were reverted (`204d7c6f`, `b4a69d6b`) because saved connectors stored `ssl=True` by default, so every saved PostgreSQL connector looked TLS-required and Gate-8 destination sampling failed against servers without TLS. `766ae6d3` made TLS-required an explicit user choice (`ssl_mode`), `8309825a` removed the `allow_ssl_downgrade` opt-out, and `51eae944` / `bbf56ed8` re-applied the two reverted commits. Consequence for QA: a connector saved before `ssl_mode` still negotiates TLS and may use plaintext until it is re-saved with SSL on.
- **D180 (SQLite on the persistent volume) is not approved.** The production default root first landed in `da81e6c3`, then was put behind `DATAFLOW_CONFINE_LOCAL_FILES` (default off) in `0c3d6340`.
- **D93** waits for a policy decision. **D31/D57** are classed as already in production by the task owner.
- **Flag-gated hardening** (tenant IP allowlist, IAM/SCIM, egress, local-file roots) ships audit-first: defaults keep pre-hardening behaviour and write would-apply events.
- **D177** is partial and **D181** is partial by decision: neither is claimed beyond what was reproduced.
